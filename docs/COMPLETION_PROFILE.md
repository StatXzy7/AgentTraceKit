# 请求退避、运行预算与恢复

默认 `codex_clean_single_turn=true`，`codex_completion_recovery=false`。正式单轮任务从冻结基线开始；不能用续接隐去失败或制造首轮完成。

专用 Codex 连接使用回环 relay，CLI provider 默认关闭自身请求/流重试，避免层层叠加。响应尚未向 CLI 交付时，408/429/500/502/503/504 或传输故障在同一请求内最多尝试 10 次（含首次）；延迟从约 30 秒指数增长到约 600 秒，并加抖动、尊重 Retry-After。等待可中止，计入单侧预算。已经开始交付的响应不重放。

认证、权限、余额不足、无法识别的错误停止自动重试。工具执行被 sandbox 拒绝会留在原轨迹，模型可在当前会话处理；不自动提升权限。是否最终成功仍由完整退出与原件完成校验决定。

默认并发 2 Pair，配置上限 16 Pair；默认单次 1800 秒，单侧总预算 14400 秒。Claude 干净尝试上限默认 12；Codex 模式依专用 relay 和运行策略处理，不可把上限相乘当作完成保证。

手动干净重跑从冻结 SHA 创建新工作区与会话，并保留旧尝试/评审，开始新的有界预算。重启服务与自动恢复保留既有预算。详情见 [干净单轮](CLEAN_SINGLE_TURN.md)。

如确需续接，必须显式选择 `codex_clean_single_turn=false`、`codex_completion_recovery=true`，并核对所在 CLI/连接模式的支持。`codex_stream_max_retries`、`codex_relay_max_attempts` 和侧尝试/总时限共同约束恢复；工作区与原 SessionID 保留，额外轮次如实记载。此模式不能被导出为生产单提示词协议通过。

配置改变供后续进程使用；已启动 CLI 不热加载。供应商配额、流实现、网络代理和机器资源需要另行验证，单元测试不保证真实模型接口可用。
