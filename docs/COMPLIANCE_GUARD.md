# Pair 正式运行与标注合规保护

执行协议版本：`2026-10-04-single-agent-v1`。本说明覆盖配置隔离、额外 Agent 检查和评审证据绑定；视频规则见 [Linux 演示](LINUX_DEMO.md)。默认人工评审，独立授权的辅助评价例外见 [授权说明](AUTHORIZED_REVIEW.md)。

## 正式运行

- 每个 Pair 使用交付台内独立的 CODEX_HOME 或 CLAUDE_CONFIG_DIR；不修改用户全局配置。专用连接继续绑定原连接版本和模型。
- 继承模式只复制允许清单内的认证、供应商和模型字段；个人 rules、agents、skills、hooks、插件、MCP 和开发指令不继承。无法安全迁移的自定义认证会明确报错，改用交付台专用连接。Python 3.10 的 Codex TOML 继承需升级到 3.11+，或使用专用连接。
- 继承配置在首次正式启动时冻结，A/B 和重跑使用同一份已筛选配置；之后修改全局供应商或默认模型仅影响新任务。认证令牌可在隔离目录正常刷新，冻结文件按私有凭据权限保存，Windows 的冻结认证字段使用同账号 DPAPI 保护。
- 配置目录若已有个人指令或扩展，停止运行并保留文件；不自动删除污染目录。
- Codex 每次启动及续接都显式关闭 multi_agent 和 multi_agent_v2。启动前读取有效功能清单，任一值未证明为 false 则停止。Claude 禁用 Agent/Task，且只提供文件、shell、网页读取和本地任务记录的明确工具清单；限制设置来源和 MCP，检查 CLI 参数支持情况，初始化若出现额外工具则终止。
- Codex 会自行安装内置 system skills。框架通过本机 app-server 元数据接口、临时隔离目录和文件哈希核对这些文件来自当前 CLI，再读取实际工作区的 skill 清单，显式禁用并复查所有条目（包括内置 review-agent）；这些预检不创建模型会话。个人扩展、改写的内置文件、未生效的禁用参数均停止运行。
- Windows 若个人 skill 清单较长，请将 Codex 命令配置为同一安装包的原生 `codex.exe`；npm `.cmd` 包装器受命令长度限制，预检失败时不会启动模型。Linux 使用服务器现有原生 CLI。
- 禁止额外做题 AI 的协议放在 CLI 系统/开发指令中，原业务提示词保持原文。普通 shell、测试、本地任务记录和题目要求的 AI 产品功能仍可使用。
- 每次尝试保存 `*-policy.json`，包含协议、原提示词、配置、有效能力输出和启动参数的哈希，不保存认证内容。失败尝试、旧工作区及原轨迹继续保留。

这是执行防护与证据门禁，不是操作系统级网络或进程隔离。任意脚本可能间接调用模型，因此不能承诺杜绝所有规避方式。

## 原轨迹门禁

同一解析器用于收尾、自检、人工锁定和严格导出，读取原 JSONL 并保存物理行号。同步返回、异步启动、user task-notification 和 attachment.queued_command 都纳入检查。

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| clear | 已检查原件，未检出实际委派或待核调用 | 仍需人工语义质审，不自动记“官方质检通过” |
| issue | 有实际额外 AI 派发证据 | 不标记成功交付，不允许锁定/严格导出有效标注 |
| needs_review | 委派缺明确返回，或有模型 CLI/API 命令需按题面解释 | 留待核，不冒充成功、权限拒绝或完整质审 |
| not_verified | 原件缺失、无法读取或 JSONL 损坏 | 无法完成核验，不允许作为有效原件交付 |

权限明确拒绝的调用记录为 blocked，不能称已启动。API 504 等错误不证明权限拒绝；启动后终止或没有完整报告，也不能抹去真实派发。TaskCreate/TaskUpdate 等本地任务记录、工具清单、讨论过但未执行的委派不算另一 AI。

模型 CLI/API 命令只是候选，不能把题目自身的 AI/Agent 产品误当做额外做题协助。工作台会显示人工核验入口，要求填写题面依据、实际用途和核验人。确认绑定原件 SHA256 和调用 ID，原件变动后失效；实际 Agent/Task/spawn_agent 派发不可通过该入口豁免。

锁定评审时绑定题面哈希、初始快照、两侧 Session、结束快照和原轨迹哈希。正式导出重新读取原件；锁定后更换原件或绑定需要解锁并重新核验。作废记录可以保留失败证据，不包装成有效交付。草稿导出不能绕过正式导出门禁成为合规声明。

## 人工标注仍需核实

锁定前逐项阅读题面、两侧完整性描述、分数、GSB 理由和结论，并回查原轨迹与固定代码：

1. 题面未写明的前提不能当作原始要求。Windows 要求不等于题面另行要求 UTF-8；真实 GBK 报错可据实描述。
2. 明确区分产品缺陷、测试预期错误、环境问题和外部检查故障，不因外部流程失败直接扣产品分。
3. 精确测试数、全部通过、首次成功等说法须对应本题、本侧、本次输出；测试数不等于覆盖场景数。
4. 分数应与已披露的完成情况一致，GSB 综合偏好可以考虑其他真实维度，最后结论与侧别需一致。
5. 不以语言工整推断 AI 来源；代码字符串、引用和题目自身的 AI 功能需按语义区分。难度不强制只有困难/地狱，GSB 不以字数或固定三个标签替代内容核验。

代码仅对明确的最终偏好矛盾和题面未出现的 UTF-8 前提做窄范围提示，不声称能全面判断每项断言。生产的单提示词执行协议单独标识，不把它当作官方质审的重复提示词或轮数规则。

已有错误轨迹应保留；需要合规的新结果时，从原始冻结提交创建干净工作区和新会话重跑，不能删调用行、拼接会话或替换原件后继续沿用旧评价。

## 只读批量复核

```powershell
$env:PYTHONPATH = 'src'
python -m agent_trace_kit.compliance --jobs-dir C:\AgentTraceKit-data\desk\jobs --output audit.json
python -m pytest -q tests/test_compliance.py
```

批量报告明确记录 `semantic_review=NOT_RUN`。它不修改评分、GSB、业务表或原轨迹。全量官方语义审核仍按指定 skill 的范围、原件与固定提交执行。

更新部署必须先确认队列空闲，保留旧 release 与私有数据备份，在新 release 中安装测试后切换服务。回滚切回原 release，任务数据和失败证据原位保留。
