# 可用性与改进说明 / Usability and improvements

0.5.0 汇总现有完整框架逻辑，提供源码安装、双 CLI、Linux 演示、失败恢复和严格证据导出。GitHub main 的源码版本独立于 PyPI 发布和服务器部署。

## 可用范围

| 能力 | 可用条件 | 验证边界 |
| --- | --- | --- |
| 会话采集、离线浏览、哈希验证 | Python 3.10+；可读取原始文件 | 合成 fixture 覆盖；`atk demo --synthetic` 不调用模型 |
| Pair 网页工作台 | Python、Git、回环端口 | Windows/Ubuntu 框架测试；关闭浏览器任务继续 |

| 授权 AI 辅助评价 | 私有授权、完整 20 任务收据及指定生成模型 | 保留 AI 来源；用户判有效性；Windows worker 另需私有配置 |

## 本版改进

1. **同源比较**：新增 GitHub 指定 commit 基线，连接版本与模型固定到 Pair；本地/新建仓库同样从冻结 SHA 创建 A/B 和重跑，清除副本中冻结后新增文件。共享 Git 元数据的 linked worktree 安全拒绝；本地复制不支持子模块，使用 GitHub commit 模式。
2. **失败可追溯**：请求层有限退避、手动干净重跑、跨重启预算、每次尝试台账和失败事后快照分别记录；不拼接成功原件、不覆盖旧评价。
3. **执行环境更清晰**：独立 CLI home、认证/provider/model 允许清单、禁用额外 Agent 与 skills 的动态预检；Windows 隐藏后台窗口，Linux 使用所属进程组清理。
4. **交付更容易复核**：实时日志、演示报告、结果 ZIP、真实视频、可读终端输出；Linux 单桌面演示串行，避免 A/B 串屏。视频仍受 89 秒限制。
5. **导出更可靠**：核对原件、冻结 SHA、明确的模型一致性、锁定证据及评审来源；授权 AI 草稿不能获得虚假的人工无 AI 声明。
6. **安装默认值可用**：去掉个人基线路径、默认评审人及硬编码生产 worker 身份；worker 通过私有配置显式绑定授权、20 个任务、SSH 主机与精确恢复收据。
7. **验证可复现**：Windows/Ubuntu Python 3.11 CI，限定 `tests` 框架目录；版本元数据与 lockfile 同步，源码安装路径与 PyPI 发布状态分开说明。

## 验证记录

当前发布的测试证据见 [GitHub Actions tests](https://github.com/StatXzy7/AgentTraceKit/actions/workflows/tests.yml)。以提交对应的运行结果为准；源码发布不代表当前生产服务器已升级。

本地 Windows 最终全套框架测试：**801 passed, 5 skipped**（Python 3.13.9）。冻结基线、独立 Git 元数据、显式及继承模型不匹配、worker 私有配置均有回归验证；Python 3.11 的 Windows/Ubuntu 结果以本次提交 CI 为准。没有为本次发布调用真实生成模型，也没有进行新的生产任务、对象存储上传或真实桌面录像验收。

## 后续改进方向

- 将固定 20 任务、指定生成模型的辅助评价控制器改为通用规模协议，同时保持冻结收据和独立授权。
- 增加真实桌面集成验证，按独立测试账号/供应商测试环境验证 CLI 升级、断流、代理和凭据刷新；记录成本与具体版本。
- 为需要强隔离的部署补充独立用户/容器或作业级资源边界；继续验证异常退出后的后代进程回收。
- 提供任务、证据和私有授权的备份/恢复工具与磁盘配额提示；自动清理必须保留可审计历史。
- 收敛类型检查和格式工具的遗留诊断；当前 CI 证明测试结果，不声称完整类型或格式检查通过。
